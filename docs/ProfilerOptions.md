# ProfilerOptions

Configuration and result container for SQL query profiling operations. Defines profiling behavior, captures execution metrics, and stores analysis artifacts such as execution plans, resource usage, and timing data.

## API

### `bool CaptureExecutionPlan`
Controls whether the query execution plan is captured during profiling. When `true`, the `ExecutionPlan` and `PlanVisualization` properties will be populated if available.

### `bool CaptureTimings`
Determines if timing metrics (e.g., duration, stage timings) are recorded. Affects the `TotalProfilingDurationMs` and `ExecutionStages` properties.

### `bool CaptureResourceUsage`
Specifies whether resource consumption (CPU, memory, I/O) is measured. Populates the `ResourceUsage` property if enabled.

### `int MaxDurationMs`
Maximum allowed duration (in milliseconds) for a query to complete before profiling is forcibly terminated. A value of `0` or negative indicates no limit.

### `int WarmUpIterations`
Number of warm-up executions performed before measurement to stabilize runtime conditions. Helps reduce variance in timing results.

### `int MeasurementIterations`
Number of iterations used to compute average performance metrics. Higher values reduce noise but increase profiling time.

### `bool IncludePlanVisualization`
Indicates whether a human-readable visualization of the execution plan should be generated and stored in `PlanVisualization`.

### `string QueryId`
Unique identifier for the profiled query, used for correlation in logs, metrics, and analysis results.

### `string QueryText`
The SQL query statement being profiled. May be truncated or sanitized depending on configuration.

### `DateTime ProfiledAt`
Timestamp indicating when the profiling operation began.

### `ProfilerOptions Options`
Reference to the original or default `ProfilerOptions` instance used as a base configuration. Used for inheritance or fallback behavior.

### `double PerformanceScore`
Normalized performance metric (0–100) representing query efficiency relative to expected or baseline performance. Higher values indicate better performance.

### `double TotalProfilingDurationMs`
Total elapsed time (in milliseconds) from start to completion of the profiling session, including warm-up and measurement.

### `bool HasError`
Indicates whether an error occurred during profiling. When `true`, `ErrorMessage` contains details.

### `string? ErrorMessage`
Descriptive message explaining the cause of a profiling error, if `HasError` is `true`.

### `QueryAnalysisResult? AnalysisResult`
Structured analysis of the query, including recommendations, warnings, and optimization suggestions. Populated if analysis is enabled and successful.

### `QueryPlan? ExecutionPlan`
Raw execution plan generated by the database engine during profiling. Includes operator details, costs, and cardinality estimates.

### `PlanVisualization? PlanVisualization`
Human-readable representation of the execution plan (e.g., formatted tree or tabular view), generated if `IncludePlanVisualization` is `true`.

### `List<ExecutionStage> ExecutionStages`
Ordered list of execution stages (e.g., parsing, optimization, execution) with timing and resource metrics for each phase.

### `ResourceUsage? ResourceUsage`
Aggregated resource consumption metrics (CPU time, memory allocation, I/O operations) during query execution. Only populated if `CaptureResourceUsage` is `true`.
