# IAnalysisPlugin

The `IAnalysisPlugin` interface defines the contract for extensible query analysis modules within the `sql-query-analyzer` project, enabling the dynamic registration, lifecycle management, and asynchronous processing of SQL queries. Implementations of this interface serve as discrete units of logic that can be plugged into the `PluginManager` to inspect, validate, or transform query execution plans and results, supporting a modular architecture where plugins can be enabled, disabled, initialized, and shut down independently without affecting the core analyzer engine.

## API

The following members constitute the public surface area of the `IAnalysisPlugin` interface and its associated management context.

### `PluginManager`
Represents the static or contextual entry point for managing plugin instances. This member provides access to the registry responsible for orchestrating the lifecycle of all loaded plugins.

### `RegisterPluginAsync`
Asynchronously registers a new plugin instance with the manager.
*   **Parameters**: Accepts an instance of a class implementing `IAnalysisPlugin`.
*   **Return Value**: Returns a `Task` that completes when the plugin is successfully added to the registry and its `InitializeAsync` method has been invoked.
*   **Exceptions**: Throws if the `PluginId` already exists in the registry or if the initialization phase fails.

### `UnregisterPluginAsync`
Asynchronously removes a plugin from the active registry.
*   **Parameters**: Accepts the unique identifier (`PluginId`) or the plugin instance to remove.
*   **Return Value**: Returns a `Task` that completes after the plugin's `ShutdownAsync` method has executed and the instance is dereferenced.
*   **Exceptions**: Throws if the specified plugin is not found in the registry.

### `ProcessThroughPluginsAsync`
Executes a query analysis pipeline by passing a query context through all currently enabled plugins in a defined order.
*   **Parameters**: Accepts the query context or SQL string to be analyzed.
*   **Return Value**: Returns a `Task<QueryAnalysisResult>` containing the aggregated findings, warnings, or errors generated by the chain of plugins.
*   **Exceptions**: May throw if a specific plugin fails during processing, potentially halting the pipeline depending on configuration.

### `GetPluginCount`
Retrieves the total number of plugins currently registered in the manager, regardless of their enabled state.
*   **Return Value**: Returns an `int` representing the count.

### `GetPlugins`
Returns a snapshot list of all registered plugin instances.
*   **Return Value**: Returns a `List<IAnalysisPlugin>`. Modifications to this list do not affect the internal registry.

### `GetPlugin`
Retrieves a specific plugin instance by its unique identifier.
*   **Parameters**: Accepts a `string` representing the `PluginId`.
*   **Return Value**: Returns an `IAnalysisPlugin?` (nullable). Returns `null` if no plugin with the matching ID is found.

### `PluginId`
An abstract property defining the unique identifier for the plugin.
*   **Return Value**: Returns a `string`. This value must be unique across all registered plugins to prevent registration conflicts.

### `Name`
An abstract property providing the human-readable display name of the plugin.
*   **Return Value**: Returns a `string`.

### `Version`
An abstract property indicating the semantic version of the plugin.
*   **Return Value**: Returns a `Version` object.

### `IsEnabled`
A boolean property indicating whether the plugin is currently active and should be included in the `ProcessThroughPluginsAsync` execution chain.
*   **Return Value**: Returns `true` if active, `false` otherwise.

### `InitializeAsync`
A virtual method called once when the plugin is registered. Used for setting up resources, connections, or configuration states.
*   **Return Value**: Returns a `Task`.
*   **Behavior**: The default implementation returns a completed task; overrides should perform asynchronous setup logic.

### `ProcessAsync` (Abstract)
The core abstract method that implementations must override to define the specific analysis logic.
*   **Parameters**: Accepts the query context required for analysis.
*   **Return Value**: Returns a `Task<QueryAnalysisResult>` containing the specific findings of this plugin.
*   **Behavior**: Must be implemented by every concrete plugin.

### `ProcessAsync` (Override)
Indicates explicit overrides of the processing logic in derived classes, ensuring the asynchronous contract is maintained while potentially adding specific typing or behavior refinements.
*   **Return Value**: Returns a `Task<QueryAnalysisResult>`.

### `ShutdownAsync`
A virtual method called when the plugin is unregistered or the application is terminating. Used for cleaning up resources.
*   **Return Value**: Returns a `Task`.
*   **Behavior**: The default implementation returns a completed task; overrides should perform asynchronous cleanup logic.

## Usage

### Example 1: Implementing and Registering a Custom Plugin
This example demonstrates creating a concrete implementation of `IAnalysisPlugin` that detects `SELECT *` usage and registering it with the `PluginManager`.

```csharp
public class SelectStarAnalyzer : IAnalysisPlugin
{
    public string PluginId => "com.sqlanalyzer.select-star";
    public string Name => "SELECT * Detector";
    public Version Version => new Version(1, 0, 0);
    public bool IsEnabled { get; set; } = true;

    public Task InitializeAsync()
    {
        // Setup resources if needed
        return Task.CompletedTask;
    }

    public abstract Task<QueryAnalysisResult> ProcessAsync(QueryContext context);
    
    // Actual implementation logic
    public override async Task<QueryAnalysisResult> ProcessAsync(QueryContext context)
    {
        var result = new QueryAnalysisResult();
        if (context.RawQuery.Contains("SELECT *", StringComparison.OrdinalIgnoreCase))
        {
            result.Warnings.Add("Avoid using SELECT *; specify explicit columns for performance.");
        }
        return await Task.FromResult(result);
    }

    public Task ShutdownAsync()
    {
        // Cleanup resources
        return Task.CompletedTask;
    }
}

// Registration usage
var plugin = new SelectStarAnalyzer();
await PluginManager.RegisterPluginAsync(plugin);
```

### Example 2: Orchestrating Analysis Across All Plugins
This example shows how to retrieve a specific plugin by ID, verify its status, and execute the full analysis pipeline.

```csharp
public async Task AnalyzeQueryAsync(string sqlQuery)
{
    // Retrieve a specific plugin to check its version
    var plugin = PluginManager.GetPlugin("com.sqlanalyzer.select-star");
    if (plugin != null && plugin.IsEnabled)
    {
        Console.WriteLine($"Running analysis with {plugin.Name} v{plugin.Version}");
    }

    // Execute the query through all registered and enabled plugins
    var context = new QueryContext(sqlQuery);
    try 
    {
        QueryAnalysisResult finalResult = await PluginManager.ProcessThroughPluginsAsync(context);
        
        Console.WriteLine($"Analysis Complete. Found {finalResult.Warnings.Count} warnings.");
        foreach (var warning in finalResult.Warnings)
        {
            Console.WriteLine($"- {warning}");
        }
    }
    catch (Exception ex)
    {
        Console.WriteLine($"Analysis failed: {ex.Message}");
    }
}
```

## Notes

*   **Thread Safety**: The `PluginManager` methods (`RegisterPluginAsync`, `UnregisterPluginAsync`, `ProcessThroughPluginsAsync`) are designed to be thread-safe. However, implementations of `ProcessAsync` within individual plugins must ensure their internal state is thread-safe if the manager invokes multiple plugins concurrently.
*   **Initialization Order**: `InitializeAsync` is guaranteed to be called exactly once per registration before any call to `ProcessAsync`. If `InitializeAsync` throws an exception, the registration fails, and the plugin is not added to the count returned by `GetPluginCount`.
*   **Nullable Returns**: The `GetPlugin` method returns a nullable reference (`IAnalysisPlugin?`). Callers must perform null checks before accessing properties like `Name` or `Version` to avoid `NullReferenceException`.
*   **Execution Flow**: The `ProcessThroughPluginsAsync` method typically short-circuits or aggregates results based on the severity of errors returned by individual `ProcessAsync` calls. If a plugin throws an unhandled exception during processing, the entire pipeline may fail unless the manager implements specific error isolation logic.
*   **Lifecycle Management**: It is critical to call `UnregisterPluginAsync` during application shutdown to ensure `ShutdownAsync` is executed, preventing resource leaks such as open database connections or file handles held by the plugin.
